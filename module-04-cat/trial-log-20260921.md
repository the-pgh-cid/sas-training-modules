### Prompt B: Zero Variance

All three runs (B1, B2, B3) used identical logic:

```python

df['first'] = df['first'].str.ljust(8)
df['middle'] = df['middle'].str.ljust(8)
df['last'] = df['last'].str.ljust(8)

# CAT: concatenate padded fields
df['name1'] = df['first'] + df['middle'] + df['last']

# CATX: strip, filter blanks, join
def catx_space(row):
    fields = [row['first'].strip(), row['middle'].strip(), row['last'].strip()]
    non_blank = [f for f in fields if f]
    return ' '.join(non_blank)

df['name2'] = df.apply(catx_space, axis=1)

# Pad results to 24 chars
df['name1'] = df['name1'].str.ljust(24)
df['name2'] = df['name2'].str.ljust(24)
```

**Correctness**: 3/3 (100%)

## Teaching Points

### Multiple Idioms in Python

String concatenation in Python can be done via:
- `+` operator: `'a' + 'b' + 'c'`
- `.join()` method: `''.join(['a', 'b', 'c'])`
- f-strings: `f'{a}{b}{c}'`
- `.str.cat()` in pandas

**The trap**: All are valid Python, but only one matches SAS semantics for this specific case.

### Uncertainty Signals

A2's behavior - showing two approaches - is a **rare glimpse of model uncertainty**. The agent couldn't decide which approach was correct, so it hedged by providing both.

This is valuable teaching data: it shows the model itself is uncertain about the best approach when constraints are loose.

### Partial Correctness

A3 demonstrates **partial correctness** - got one part right (filtering) but missed others (padding, stripping). This is common in real-world LLM usage: the model understands part of the requirement but not all edge cases.
