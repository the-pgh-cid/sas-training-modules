## Why No Variance?

### 1. Obvious pandas Functions

**String to numeric**:
```python
pd.to_numeric()  # Universal pattern
```

**String to datetime**:
```python
pd.to_datetime(format='...')  # Standard approach
```

**No alternatives** that are equally obvious. Unlike COMPRESS ('ka' modifier confusion) or SUBSTR (indexing traps), type conversion has one clear path.

---

### 2. Well-Documented Format Specifications

**Date format `'%d%b%Y'`**:
- `%d` = day (01-31)
- `%b` = month abbreviation (JAN, FEB, ...)
- `%Y` = 4-digit year

**This is standard Python datetime formatting** - not SAS-specific, not ambiguous, not subject to interpretation.

---

### 3. No Edge Cases in Test Data

**Test inputs**:
- `["123", "456", "789"]` - clean numeric strings
- `["15JAN2023", "01FEB2023", "31DEC2023"]` - valid dates

**No edge cases to expose**:
- No malformed numbers
- No invalid dates
- No timezone issues
- No ambiguous formats

**Contrast with**:
- **Module 3 (LENGTH)**: Lucky test data hid semantic errors
- **Module 5 (ROUND)**: Lucky test data avoided .5 cases
- **Module 8 (INPUT)**: Test data is straightforward, not "lucky" - the task itself is simple

## Teaching Value

### Show the Baseline

"Modules 1 and 8 represent what 'easy' looks like for LLMs:"
- Solution is obvious
- Strong prior knowledge
- Well-documented functions
- No competing idioms
- Result: Zero variance, 100% correctness

### Contrast with "Hard" Modules

**Easy (Module 8)**: Type conversion
- `pd.to_numeric()` - one obvious function
- `pd.to_datetime()` - standard format specs
- Zero variance

**Hard (Module 2)**: Substring extraction
- Python 0-indexed, SAS 1-indexed
- Multiple approaches (.str[] vs .str.slice())
- 0% correctness, high variance

**Hard (Module 7)**: COMPRESS with modifiers
- 'ka' = "keep alphabetic" (confusing)
- "Alphabetic" vs "alphanumeric" (terminology trap)
- 67% correctness

### The Spectrum

**Easy → Hard**:
1. **Type conversion** (Module 8): Universal patterns
2. **Arithmetic** (Module 1, 6): Well-defined math
3. **String manipulation** (Module 2, 7): Semantic differences
4. **Formatting** (Module 3, 4, 5): Edge cases and traps
