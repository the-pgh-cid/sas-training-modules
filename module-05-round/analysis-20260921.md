## The Awareness Variance Problem

### What is Awareness Variance?

**Awareness variance** occurs when:
- All runs produce correct output
- All runs use the same method
- But runs differ in their *understanding* of edge cases or semantic differences

**Why it's dangerous**:
- Tests pass (output is correct)
- Code looks reasonable (method is standard)
- But hidden semantic errors will trigger when edge cases appear
- Developer may trust incorrect explanations in comments/notes

## The Banker's Rounding Landmine

### What is Banker's Rounding?

**Banker's rounding** (round-half-to-even): When value is exactly halfway (.5), round to the nearest even number.

```python
round(2.5)  # → 2 (round to even)
round(3.5)  # → 4 (round to even)
round(4.5)  # → 4 (round to even)
```

**SAS rounding** (round-half-away-from-zero): When value is exactly halfway, round away from zero.

```sas
round(2.5)  /* → 3 (away from zero) */
round(3.5)  /* → 4 (away from zero) */
round(4.5)  /* → 5 (away from zero) */
round(-1.5) /* → -2 (away from zero) */
```

### The Difference

| Value | Python `.round()` | SAS `round()` | Differ? |
|-------|-------------------|---------------|---------|
| 2.3   | 2                 | 2             | No      |
| 2.5   | **2** (to even)   | **3** (away)  | **YES** |
| 2.7   | 3                 | 3             | No      |
| 3.5   | 4 (to even)       | 4 (away)      | No      |
| 4.5   | **4** (to even)   | **5** (away)  | **YES** |
| -1.5  | -2 (to even)      | -2 (away)     | No      |
| -2.5  | **-2** (to even)  | **-3** (away) | **YES** |

**Pattern**: Difference only appears for some .5 cases (those where "to even" differs from "away from zero").

## Appendix: The Math Behind Banker's Rounding

### Why "Round Half to Even"?

Banker's rounding minimizes bias in aggregate calculations:

```python
# Round half away from zero (SAS):
values = [0.5, 1.5, 2.5, 3.5, 4.5]
sum(sas_round(values))  # → 0+2+3+4+5 = 14 (always rounds up)

# Round half to even (Python):
sum(round(v) for v in values)  # → 0+2+2+4+4 = 12 (balances up/down)

# True mean of original: 2.5
# Mean after SAS rounding: 14/5 = 2.8 (upward bias)
# Mean after Python rounding: 12/5 = 2.4 (downward bias, but less)
```

**Why SAS doesn't use it**: SAS predates banker's rounding as standard. Backward compatibility matters more than statistical bias reduction for business applications.

**Why it matters for migration**: Existing SAS reports will show different numbers if you use Python's default `.round()`.
