## The Lucky Consistency Problem

**What happened**: All six runs produced correct output.

**Why this is "lucky"**: 
- Test data avoids .5 values where SAS/Python differ
- Prompt A runs showed variance in *understanding* (A1 wrong, A2/A3 right)
- But variance in understanding didn't cause variance in output because test data is kind

**The landmine**:
```python
# For value = 2.5:
df['value'].round()  # Python: 2.0 (banker's rounding - round to even)
# SAS round(2.5)      # SAS: 3 (round half away from zero)

# For value = 3.5:
df['value'].round()  # Python: 4.0 (banker's rounding - round to even)
# SAS round(3.5)      # SAS: 4 (round half away from zero)
```

**Result**: Python's banker's rounding produces different results than SAS for halfway cases.

## Teaching Points

### The Awareness Variance Pattern

Module 5 introduces a new variance type: **awareness variance**. 

- **Output**: All correct (100%)
- **Method**: All consistent (`.round()`)
- **Understanding**: Varied (33% correct vs 67% incorrect/incomplete)

**The trap**: When output is correct but understanding is wrong, the error is hidden until edge cases appear.

**Pattern**: Well-chosen test data can mask semantic differences.
