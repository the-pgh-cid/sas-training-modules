## Two Valid Approaches

**Prompt A: Position Tracking**
```python
df['first_flag'] = (df.groupby('group').cumcount() == 0).astype(int)
df['last_flag'] = (df.groupby('group').cumcount() == size - 1).astype(int)
```
**Concept**: Track position within group (0, 1, 2, ...), flag position 0 and N-1.

**Prompt B: Boundary Detection**
```python
df['first_flag'] = (df['group'] != df['group'].shift(1)).astype(int)
df['last_flag'] = (df['group'] != df['group'].shift(-1)).astype(int)
```
**Concept**: Detect when group value changes from previous/next row.

**Both produce correct output**: [1,0,1,0,0,1] and [0,1,0,0,1,1]

---

## Why Two Approaches?

**SAS FIRST./LAST. semantics**:
```sas
by group;
first_flag = first.group;  /* 1 when group changes from previous */
last_flag = last.group;    /* 1 when group changes to next */
```

**Can be interpreted as**:
1. **Position**: "Am I at position 0 or N-1 in my group?"
2. **Boundary**: "Does my group differ from neighbor's group?"

For sorted data, both interpretations produce identical results.

---

## Trade-offs

| Aspect | cumcount() (A) | shift() (B) |
|--------|----------------|-------------|
| Conceptual clarity | ✅ "Position 0" | ✅ "Differs from neighbor" |
| Mirrors SAS logic | ❌ Not directly | ✅ Directly mirrors BY |
| NaN handling | ✅ Not needed | ⚠️ Must understand |
| Group size needed | ✅ Yes (for last) | ❌ No |
| Code length | ~Equal | ~Equal |

**Neither is "wrong"** - choice based on interpretation and preference.

## The Row 6 Edge Case

**Test data**:
```
Row 1: id=1, group=A → first_flag=1, last_flag=0
Row 2: id=2, group=A → first_flag=0, last_flag=1  (last of group A)
Row 3: id=3, group=B → first_flag=1, last_flag=0  (first of group B)
Row 4: id=4, group=B → first_flag=0, last_flag=0
Row 5: id=5, group=B → first_flag=0, last_flag=1  (last of group B)
Row 6: id=6, group=C → first_flag=1, last_flag=1  (BOTH!)
```

**Row 6 is critical**: Single-row group C has both flags = 1.

**All runs handled this correctly** - no edge case failures.
